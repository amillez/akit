### Session pickup

**You own the resume point. Read the prior trail, don't redo it.**

1. Locate the prior trail: the resume note or handoff message you were given, the pushed branch and its PR, and the prior agent's session log when you can reach it (Claude Code keeps sessions under `~/.claude/projects/<project>/`, Codex under `~/.codex/sessions/`). Read the session for this task first. Earlier sessions from the same project on the same subject (the same feature, file, subsystem, or bug) are fair game when the current trail is thin. Find them in that project's Claude Code directory, or by the working directory recorded at the top of each Codex session, then match on opening prompts or topic. Never read sessions from other projects. Read the last messages first, then scan back for the decision points. Parse a long log in a subagent and keep the reduced timeline in the main thread ([Guard the Context Window](../principles/guard-the-context-window.md)).
2. Reconstruct operational state. The branch and worktree, what already landed (`git log`, `git diff` against the base, `gh pr view`), the open todos, the decisions made, and any review threads still open. The prior trail is authoritative input. Resist the bias to re-derive it.
3. Sweep the shared record when the work names a feature, file, subsystem, or bug. The session log holds what the prior agent did. The shared record holds what happened around the same code under other names: symptoms users keep reporting, fixes that shipped and got reverted, errors still firing, and committed decision trails (the [`show-me-your-work`](../../show-me-your-work/SKILL.md) skill). Ask what the current state is, what was tried and didn't hold, and what is still reported.
   - Git history: `git log -S '<symbol>'` and `git log -G '<regex>'` to find the commits that introduced or changed the code, `git log --grep=Revert` for fixes that didn't hold, `git blame -L <range> <file>` on the lines in play, then `gh pr view <number> --comments` on the introducing PR for its intent and review.
   - Issues and PRs: `gh issue list --search '<topic>' --state all` and `gh pr list --search '<topic>' --state all`.
   - The issue tracker, error tracker, and team docs through their connected tools, when reachable. Skip an unavailable source and say so. A search that finds nothing is still a finding.
   Run the sweep in a subagent and keep only its findings in the main thread. Skip it only for pure activity recall with no named target.
4. Diff done vs pending. Compare what shipped against what was planned, name the resume point, do not re-run the prior repro or redo completed work. A "let me verify from scratch" pass means you're treating the trail as untrustworthy when it's authoritative.
5. Route the remaining work to the matching playbook and pick the verdict: continue the execution, ship a finished recommendation, ratify or override a prior conclusion, or postmortem a failed run. The pickup playbook ends here. The routed playbook owns the rest.
6. Verify the inherited claims against the original goal on the real artifact ([Prove It Works](../principles/prove-it-works.md)). A passing prior self-report is not the proof.

**Reply:** where the prior agent stopped, what you inherited vs redid (ideally nothing redone), recurring problems and reverted fixes from the shared record with their sources (PR, issue, or commit), the resume point, and the outcome.
