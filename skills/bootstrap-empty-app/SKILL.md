# Bootstrap an empty app

**You own the tree and the startup order.** Stand up an empty Expo app with house tooling that runs in a dev client on iOS and Android. Every later playbook assumes this shape.

Use it for a new app, or to bring an app that never had the house layout up to it. This skill holds the whole procedure, so it needs no other skill loaded. When `amillez-mode` is loaded too, its process (plan, PR, never merge, babysit) still governs around these steps. The decisions live in rn-bedrock. [`examples/bedrock/`](https://github.com/amillez/rn-bedrock/tree/main/examples/bedrock) is the working reference. Copy its shape, not its product.

**Hard don'ts.** Each one is in rn-bedrock [`AGENTS.md` § Hard invariants](https://github.com/amillez/rn-bedrock/blob/main/AGENTS.md#hard-invariants) or [`docs/architecture.md` § Boundaries that hold](https://github.com/amillez/rn-bedrock/blob/main/docs/architecture.md#boundaries-that-hold).

- No import before `./polyfills` in `src/main.ts`.
- No `libs/http/`, no injected HTTP adapter, no axios. The `fetch` replacement is a global polyfill.
- No `components/` folder or `.tsx` file under `src/modules/`.
- No hand edits in `ios/` or `android/`. They are prebuild output and gitignored.
- No Expo Go. The stack has native code from the first commit (`react-native-nitro-fetch`).
- None of the five libraries agents wrongly assume: Unistyles, NativeWind, Expo Router, axios, FlashList.
- No change to Metro, Babel, or a pinned version before you read [`docs/workarounds.md`](https://github.com/amillez/rn-bedrock/blob/main/docs/workarounds.md).
- No deleting another project's DerivedData, Gradle, or Metro caches to make room, even orphaned ones. Remove only this run's own outputs.

1. Read, in order: [`AGENTS.md`](https://github.com/amillez/rn-bedrock/blob/main/AGENTS.md), [`docs/architecture.md` § The shape](https://github.com/amillez/rn-bedrock/blob/main/docs/architecture.md#the-shape) and [§ Bootstrap order](https://github.com/amillez/rn-bedrock/blob/main/docs/architecture.md#bootstrap-order), [`docs/tooling.md`](https://github.com/amillez/rn-bedrock/blob/main/docs/tooling.md), [`docs/stack.md` § Platform](https://github.com/amillez/rn-bedrock/blob/main/docs/stack.md#platform) and [§ Pins worth knowing about](https://github.com/amillez/rn-bedrock/blob/main/docs/stack.md#pins-worth-knowing-about), and [`docs/workarounds.md`](https://github.com/amillez/rn-bedrock/blob/main/docs/workarounds.md).
2. Create the project with pnpm on the Expo SDK, React Native, and React versions in `docs/stack.md` § Platform. Set `"main": "./src/main.ts"` and copy the script names from [`docs/tooling.md` § Commands](https://github.com/amillez/rn-bedrock/blob/main/docs/tooling.md#commands). `start` runs `expo start --dev-client`. Pass the Metro port at run time, not in the script. Pin `react-native-reanimated` and `react-native-worklets` at the exact versions `docs/stack.md` names. Then age-gate every version per [agent-use-policy §11](https://github.com/amillez/ai-eng-practices/blob/main/policies/agent-use-policy.md#11-dependency-versions): at least 1 month old and no significant reported issues. Only host tooling on `agent-m1` is exempt.
   - **Gate inside the SDK's ranges.** For a package the Expo SDK manages, pick inside its range in `expo/bundledNativeModules.json` for that SDK, not the newest on npm. A required exact pin wins over the gate's newest pick: a `docs/stack.md` exact pin, or a peer the platform requires (React and `react-dom` at the version the React Native renderer needs). Log each one with its reason. A pin still has to pass both checks. Anything newer waits, including a `docs/stack.md` version that fails either check.
   - **Run the issue check on every direct dependency.** Cover every entry in `dependencies` and `devDependencies` of the final `package.json`, not only the versions you picked, and diff the two lists before you log no holds. For each, read the package repo's open issues and the changelogs of the releases after your pick for crash or regression reports on the version, for example `gh issue list -R <owner>/<repo> --state open --search "<version> crash"` and again with `regression`. Hold a pick with an open crash or regression on a platform you ship, and take the previous version that passes. Log every held pick and every open issue you accepted, with its link, for the reply.
   - **Enforce the age in config.** Set pnpm `minimumReleaseAge` in `pnpm-workspace.yaml` to the value policy §11 gives, so pnpm gates transitive dependencies too. Exclude a package with `minimumReleaseAgeExclude` only for a required pin, and log it.
3. Lay out the canonical tree from `docs/architecture.md` § The shape: `src/main.ts`, `src/polyfills/`, `src/libs/`, `src/modules/`, `src/utils/`, and `src/ui/` with `providers.tsx`, `navigator.tsx`, `screens/`, `components/`, `navigation/`, `locale/`, and `query/`. Add `plugins/`, `global.css`, and `app.config.ts` at the root. Commit a `.gitkeep` in every folder that starts empty (`src/modules/`, `plugins/`), or a fresh clone won't have it.
4. Write the entry per [§ 1. Polyfills before anything else](https://github.com/amillez/rn-bedrock/blob/main/docs/architecture.md#1-polyfills-before-anything-else). `src/main.ts` imports `./polyfills`, then calls `registerRootComponent`, and nothing else. `src/polyfills/index.ts` imports `./nitro-fetch`, which replaces the global fetch stack per [nitro-fetch § Global replace](https://fetch.margelo.com/docs/global-replace). This is the whole polyfill; no other skill is needed:

   ```ts
   // src/polyfills/nitro-fetch.ts
   import { fetch, Headers, Request, Response } from "react-native-nitro-fetch";

   globalThis.fetch = fetch;
   globalThis.Headers = Headers;
   // Both type formData() against the DOM FormData; RN's global FormData declares getParts instead.
   globalThis.Request = Request as unknown as typeof globalThis.Request;
   globalThis.Response = Response as unknown as typeof globalThis.Response;
   ```
5. Compose the providers outermost first in `src/ui/providers.tsx` per [§ 2. Providers, outermost first](https://github.com/amillez/rn-bedrock/blob/main/docs/architecture.md#2-providers-outermost-first): gesture handler root, config, `SafeAreaProvider`, `SafeAreaListener` (publishes insets to uniwind), React Query's `QueryProvider`, then the overlay host. The gesture handler root wraps everything. Config wraps every provider that reads config. Safe-area mounts before the listener that publishes insets to uniwind. React Query sits inside the safe-area listener and outside the overlay host, so overlays can query. The overlay host mounts last. Sheets need no provider. Match the order and comment in the example's `src/ui/providers.tsx`.
6. Gate startup per [§ 3. Startup gates, each degrading alone](https://github.com/amillez/rn-bedrock/blob/main/docs/architecture.md#3-startup-gates-each-degrading-alone). Hold the splash on independent gates that each resolve true on failure. Only fonts and i18n block the first paint. Put the error boundary outside `Providers`, so its fallback uses nothing a provider supplies. The error fallback hides the splash when it mounts (`SplashScreen.hideAsync()` in an effect), or a provider crash leaves the splash up over the fallback. See the example's `src/ui/app.tsx`.
   - **Module-scope code catches its own errors.** Anything that runs at import time (locale reads, i18n init and its language detector, polyfills) runs before any error boundary exists, so wrap it and fall back (default language, no-op). Prove one startup failure at runtime: force a throw in one of them, show the app still renders and logs the error, then revert it. Name it in the reply.
7. Configure TypeScript per [`docs/tooling.md` § TypeScript](https://github.com/amillez/rn-bedrock/blob/main/docs/tooling.md#typescript). Extend `expo/tsconfig.base` with `strict`, `noUncheckedIndexedAccess`, and `noImplicitOverride`. Map `~/*` to `./src/*`, and make Babel, Metro, and Jest's `moduleNameMapper` resolve the same alias. Type `EXPO_PUBLIC_*` in `types/env.d.ts` and keep `.env.example` in step.
   - **TypeScript version.** `docs/stack.md` is the source of truth. While it names no TypeScript version, the one the Expo SDK expects (`npx expo install --check`) wins over the example's, passing the step 2 age gate. TypeScript 6 needs a `types/css.d.ts` with `declare module "*.css";` for the `global.css` import. Log the version and why in the reply.
8. Configure Metro per [`docs/tooling.md` § Metro](https://github.com/amillez/rn-bedrock/blob/main/docs/tooling.md#metro). Use `getSentryExpoConfig(__dirname)` as the base once the app has Sentry. Until then use `getDefaultConfig`, as the example does. `withUniwindConfig` is the outermost wrapper. Invert that order only when Worklets Bundle Mode is in the tree, per [workarounds § Bundle Mode and uniwind resolution deadlock](https://github.com/amillez/rn-bedrock/blob/main/docs/workarounds.md#bundle-mode-and-uniwind-resolution-deadlock). A custom `resolveRequest` captures the previous one and falls back to it.
9. Keep Babel minimal per [`docs/tooling.md` § Babel](https://github.com/amillez/rn-bedrock/blob/main/docs/tooling.md#babel). Use `babel-preset-expo` with `unstable_transformImportMeta: true`, plus `transform-remove-console` in production. Do not add the worklets or reanimated plugin by hand.
10. Set up logic-only Jest: Node environment, `ts-jest`, and `*.spec.ts` only. Copy the example's `jest.config.ts` and keep its `testMatch`.
11. Keep native config in `app.config.ts` per [`docs/tooling.md` § Native builds and release](https://github.com/amillez/rn-bedrock/blob/main/docs/tooling.md#native-builds-and-release). Config plugins go in `plugins/with-*.js` and read build-time data from `app.config.ts`. Gitignore `ios/` and `android/`. After any native change, run `pnpm prebuild`. Before `pnpm prebuild`, `pod install`, any native build, or an emulator boot on `agent-m1`, run the disk check from [agent-use-policy §12](https://github.com/amillez/ai-eng-practices/blob/main/policies/agent-use-policy.md#12-agent-m1-resource-limits): `df -h ~`, and under 20 GB Avail stop, ping Ben (the infra owner) with the output, or report it to your dispatcher, and wait. Use one scheme everywhere it appears.
12. Add `expo-dev-client` at the newest version that passes the step 2 age gate. Build and run with `pnpm ios` and `pnpm android`. Add `eas.json` for EAS builds. pnpm blocks dependency install scripts by default. Decide each one in `pnpm-workspace.yaml` under `allowBuilds` (`true` runs it, `false` skips it), as the example does. pnpm reads `allowBuilds` from 10.26, and pnpm 11 removed `onlyBuiltDependencies` and `ignoredBuiltDependencies`, so don't use those. After install, `pnpm ignored-builds` lists none.
   - **On a host other sessions share, Metro gets its own port.** Never use 8081. Lease a port through simfleet when the project has `.sim-fleet/project.json`. Without one simfleet gives no lease, so pick a free port outside its ranges (8100–8499), and say so in the reply. Run `pnpm start --port <N>`. `pnpm ios --no-bundler` ignores `RCT_METRO_PORT`, and `--port` clashes with `--no-bundler`, so the app it launches can attach to another session's Metro. Build and install with `pnpm ios --no-bundler` and `pnpm android --no-bundler`, then open your Metro by URL:
     - iOS: the build auto-opens the app on 8081, so right after `pnpm ios --no-bundler` finishes run `xcrun simctl terminate <udid> <bundle id>`, then `xcrun simctl openurl <udid> "exp+<scheme>://expo-development-client/?url=http%3A%2F%2Flocalhost%3A<N>"`
     - Android: `adb -s <serial> reverse tcp:<N> tcp:<N>`, then `adb -s <serial> shell am start -a android.intent.action.VIEW -d "exp+<scheme>://expo-development-client/?url=http%3A%2F%2Flocalhost%3A<N>"`
   - On first launch, dismiss the dev client's onboarding sheet before you capture proof.
   - If Metro can't resolve a package right after a reinstall, delete only this root's `$TMPDIR/metro-file-map-*` cache. Never `--clear` on a shared host; it wipes caches other sessions use.
13. Pick each library from the `docs/stack.md` § By layer table, at the newest version that passes the step 2 age gate. Before you add or swap one, read its entry in [`docs/packages/`](https://github.com/amillez/rn-bedrock/blob/main/docs/packages/README.md) and its **Rejected** list. That covers every library you add, including ones outside the table (teleport is in `overlays`, expo-font in `text-and-icons`). A skipped entry is a miss even if you report it. List every library with the entry you read, and any Rejected alternative you ruled out, for the reply.
14. Verify. Run `pnpm typecheck` and `pnpm test`. Confirm that `src/modules/` holds no `.tsx` file and that the first import in `src/main.ts` is `./polyfills`. Build the dev client on an iOS simulator (iOS 26 by default) and an Android emulator, and prove the first screen renders after the splash hides.
   - **Devices.** When simfleet runs on the host, boot, claim, and release every simulator and emulator through it (see the `simfleet` skill). Never boot or drive a device another session holds. Wait for it instead, in a bounded loop. macOS has no `timeout`, so count iterations around `sleep` and keep stderr visible.
   - **One Android emulator fleet-wide** ([agent-use-policy §12](https://github.com/amillez/ai-eng-practices/blob/main/policies/agent-use-policy.md#12-agent-m1-resource-limits)). Run the step 11 disk check, then check what is running (`simfleet status` or `simfleet emu list`, else `adb devices` and `pgrep -fl qemu-system`). If an emulator that isn't yours runs, reuse it through a simfleet claim or wait. Never boot a second one.
   - **Proof devices.** iOS 26 simulator; Android on `agent-Pixel7-api35`. When api35 is held, wait rather than boot another AVD. If you prove Android elsewhere, name the API level in the reply.
   - **Proof.** Capture a screenshot or recording on each platform, through Argent or the project's `verify-*` skill when one exists. If Argent can't capture (it can't attach to an emulator simfleet booted, for example), `xcrun simctl io <udid> screenshot <path>` or `adb -s <serial> exec-out screencap -p > <path>` is acceptable proof. Link both in the PR, or in your reply when there is no PR.
   - **Teardown** ([agent-use-policy §12](https://github.com/amillez/ai-eng-practices/blob/main/policies/agent-use-policy.md#12-agent-m1-resource-limits)). Run `./gradlew --stop` in `android/` before you delete it, then kill any daemon of this run that `pgrep -fl 'GradleDaemon|KotlinCompileDaemon'` still lists. Stop your Metro, release and shut down every simulator and emulator the run booted (through simfleet when it runs, per the `simfleet` skill), run `watchman watch-del <root>` (never `watch-del-all`), and remove any worktree you created for the run.

The domain, data, UI, and product-SDK layers are later work, each owned by an `amillez-react-native-mode` playbook: storage by `wire-storage`, query persistence by `build-queries`, remote config by `wire-config`, icons by `build-ui-components`, and Sentry by `wire-sentry`. Leave them out. A bootstrap PR stops at an app that starts, renders one screen, and passes typecheck and tests.

**Reply:** the tree you created, the provider order and gates, each pin or workaround you kept and its removal condition, the issue check (packages covered, held picks and accepted open issues, with links), the forced startup failure and its proof, each library added with the `docs/packages/` entry you read, the TypeScript version and why, the Metro port and how you got it, and the proof for both platforms with the device and API level (links, or paths when there is no PR).
